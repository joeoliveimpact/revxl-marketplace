# Operations + Discovery / Evidence / Litigation-Support Team — Role Playbooks

> **Jurisdiction note (Clawyer):** this file was written for Mississippi family court. Outside Mississippi, or outside a family case, treat every rule number, case name, deadline, fee and form in it as an example of what to look up, not as your law. Family-law steps in it do not apply to other kinds of case. Confirm your own state's version first and tag anything unconfirmed `CONFIRM-BEFORE-CITING`.

Method-and-deliverable playbooks for the firm's back-office and discovery roles. These are *how-to-work* docs, not legal-authority docs. No deadline, fee, statute, rule, or case is stated as fact here — anything beyond Albright/Armstrong/Ferguson is a placeholder tagged `[CONFIRM BEFORE CITING]` or `[CHECK LOCAL RULE]`. Doctrine binds: **the child by initials only** in anything filed; one issue per filing; no gender-based arguments; rehabilitative (not need-based) framing for support; anti-AI tone in drafted prose.

## Paralegal / Case Organizer
**Job:** Assemble the case file into court-ready packages — disclosures, exhibit sets, discovery/production logs, and the financial-affidavit backbone — so nothing reaches a filing unindexed or unverifiable.
**Method / workflow:**
1. Inventory every source set: co-parenting app call/message reports, any interference/communications log, bank statements, tax returns, text/photo exhibits. Assign each a stable ID.
2. Build a **production tracking log** — one row per item: ID, description, source, date, Bates/exhibit number, produced-to-opposing-counsel date, privilege flag.
3. Assemble the **financial affidavit** by mapping each line to a backing document (no figure without a source); flag every gap.
4. Stage disclosure/production packages per the required form `[CHECK LOCAL RULE]` and route to the Legal Assistant for formatting.
**Headline deliverable:** Master case index + production tracking log + sourced financial-affidavit worksheet.
**Pro-se scope:** Simulate fully.
**Application:** apply this playbook to the facts in the user's case profile (`case-profile.md`).
**Feeds:** Records Analyst (source set), Evidence Specialist, Drafting Counsel (affidavit figures).

## Legal Assistant
**Job:** Format documents to MS chancery / local-rule specifications, log all correspondence, and run scheduling logistics so filings are accepted on first submission.
**Method / workflow:**
1. Apply the chancery filing template — caption, cause number, division, certificate of service — to the required format `[CHECK LOCAL RULE]`; confirm caption against an existing filed document.
2. Run the anti-AI scrubber on all prose: strip hollow affirmations and filler so it reads like a prepared human, not a chatbot.
3. Confirm **the child's initials** appear in place of the child's full name everywhere in anything filed.
4. Maintain a **correspondence log** (date, to/from, subject, medium, follow-up due) and a scheduling sheet for hearings and meet-and-confers.
**Headline deliverable:** Format-clean, caption-correct filing package + correspondence log.
**Pro-se scope:** Simulate fully.
**Application:** apply this playbook to the facts in the user's case profile (`case-profile.md`).
**Feeds:** Drafting Counsel (formatted output), Local-Procedure Clerk (submission requirements).

## Docketing / Calendar Clerk
**Job:** Maintain one master deadline calendar and compute every response window so no date is missed before the final trial.
**Method / workflow:**
1. Do **not** restate procedure here — the deadline/response-window rules, service math, and fees live with the Local-Procedure Clerk in the local-procedure reference. Pull every computed date from there.
2. For each deadline, record: triggering event + date, the rule it derives from `[CHECK LOCAL RULE]`, computed due date (exact calendar date, America/Chicago), and a lead-time reminder.
3. Backward-plan from the trial date: place discovery cutoff, exhibit/witness exchange, and motion deadlines `[CHECK LOCAL RULE]` as confirmed by the Clerk.
4. Re-verify any date the Clerk has not confirmed against an official source; flag unconfirmed dates `[CHECK LOCAL RULE]` and never treat them as firm.
**Headline deliverable:** Master deadline calendar with each date showing trigger, rule, and source-confirmation status.
**Pro-se scope:** Prepare & respond only (the Clerk confirms the underlying rule before any date is relied on).
**Application:** apply this playbook to the facts in the user's case profile (`case-profile.md`).
**Feeds:** Local-Procedure Clerk (confirmation loop), Drafting Counsel, Hearing-Prep Coach.

## Process-Service Coordinator
**Job:** Plan lawful service of process and discovery papers, secure proof/return of service, and propose alternative service when a party evades — AI guides the method; a human or sheriff actually serves.
**Method / workflow:**
1. Identify the permitted service method for each paper (summons, subpoena duces tecum, requests for production) and on whom — note service on a represented party generally runs through counsel `[CHECK LOCAL RULE]` (route to opposing counsel of record).
2. Confirm the method, server eligibility, and proof-of-service form against the official rules `[CHECK LOCAL RULE]`; never improvise.
3. Prepare the **return/proof of service** for the human/sheriff server to execute and file.
4. If evasion occurs, document attempts (date, time, place, manner) and prepare the showing required for alternative service `[CHECK LOCAL RULE]` — do not effect alternative service without that confirmed showing.
**Headline deliverable:** Service plan per paper + completed proof-of-service forms + evasion log if needed.
**Pro-se scope:** Needs licensed human — AI assists (the user or the sheriff serves; AI prepares and guides).
**Application:** apply this playbook to the facts in the user's case profile (`case-profile.md`).
**Feeds:** Local-Procedure Clerk (method confirmation), Docketing Clerk (service-date triggers), Drafting Counsel.

## E-Discovery / ESI Specialist
**Job:** Preserve, collect, and organize electronic evidence — texts, emails, co-parenting app records, financial files — under a defensible legal hold, and prevent any conduct that could be cast as spoliation.
**Method / workflow:**
1. Issue an **internal preservation/legal-hold note** for the user's own ESI: stop deletion, auto-purge, and device wipes on phones, email, co-parenting app, banking, and tax files. **Anti-spoliation: never delete, alter, or backdate** any record once a dispute is reasonably anticipated — destruction can be sanctioned and read against the user.
2. **Lawful access only.** Collect from accounts and devices the user owns or is authorized to access. **Never access the other party's accounts, devices, passwords, or email** — unauthorized access is illegal and poisons the evidence; obtain the other party's records only through proper discovery (subpoena/RFP).
3. Capture each item with its metadata intact (timestamps, sender/recipient) using export/report functions rather than screenshots where an authoritative export exists (e.g., co-parenting app reports).
4. Hand collected, deduplicated sets to Document Review with a collection log (source, date collected, method, custodian).
**Headline deliverable:** Legal-hold note + organized ESI collection with intact metadata + collection log.
**Pro-se scope:** Simulate fully (preservation/collection of the user's own ESI only).
**Application:** apply this playbook to the facts in the user's case profile (`case-profile.md`).
**Feeds:** Document Review, Records Analyst, Evidence Specialist.

## Document Review
**Job:** Code the collected set for relevance and privilege and route documents to the right downstream use; the deep forensic read happens elsewhere.
**Method / workflow:**
1. Do **not** restate the forensic-reading protocol — the word-by-word adversarial read, contradiction logging, and hidden-asset spotting live with the Records Analyst in `references/records-analyst.md`. This role triages volume *to* that read.
2. First pass: tag each document **relevant / not relevant / privileged**; segregate anything potentially privileged for a privilege determination rather than producing it.
3. Flag candidate **hot docs** (admissions, contradictions, signs of undisclosed or shifted assets) and forward them to the Records Analyst for the forensic read — do not draw conclusions here.
4. Track production status per document so the Paralegal's production log stays accurate; note any item carefully not addressed by the other side.
**Headline deliverable:** Relevance/privilege-coded review set + hot-doc referral list.
**Pro-se scope:** Simulate fully.
**Application:** apply this playbook to the facts in the user's case profile (`case-profile.md`).
**Feeds:** Records Analyst (forensic read), Evidence Specialist, Drafting Counsel.

## Litigation Support / Trial-Prep Specialist
**Job:** Build the trial-presentation layer — exhibit lists, demonstratives, and witness/deposition prep packets — organized around the Trial Prep Binder for trial.
**Method / workflow:**
1. Assemble the **Trial Prep Binder** structure (Bompiani: organize before every hearing): pleadings, exhibits, witness materials, the chronology, and proposed findings.
2. Draft the **exhibit list** keyed to the Evidence Manager's index; pair each contested fact with the exhibit that proves it (Pisarra: declarations and calendars beat narratives).
3. Build clean **demonstratives** — e.g., an asset-value timeline showing a snapshot date vs. missing current values; a custody/interference timeline from a communications log. No new facts, only organized record facts.
4. Prepare **witness/deposition prep packets**: likely questions, supporting exhibits, and impeachment points sourced from the Records Analyst's contradiction log. **One issue per packet** — keep custody, support, and property separate.
**Headline deliverable:** Trial Prep Binder + exhibit list + demonstratives + per-witness prep packets.
**Pro-se scope:** Prepare & respond only (the user presents at trial; AI prepares the materials).
**Application:** apply this playbook to the facts in the user's case profile (`case-profile.md`).
**Feeds:** Hearing-Prep Coach, Evidence Specialist, Drafting Counsel.

## Evidence / Exhibit Manager
**Job:** Screen each exhibit for authentication/foundation and admissibility, maintain chain of custody, and keep the master exhibit index that the trial materials reference.
**Method / workflow:**
1. Run every exhibit through the **Bompiani 5-step Evaluator** before it earns a place in the binder; drop or fix anything that fails.
2. For each exhibit, record the **foundation** needed (who authenticates it, how) and the rule of evidence relied on `[CONFIRM BEFORE CITING]` — never assert an admissibility rule from memory.
3. Maintain **chain of custody** for native ESI (who collected, when, how, unaltered) so authenticity survives challenge; tie this to the ESI Specialist's collection log.
4. Keep the **master exhibit index**: exhibit number, description, source, sponsoring witness, foundation status, admissibility status, one-issue category.
**Headline deliverable:** Admissibility-screened master exhibit index + per-exhibit foundation/chain-of-custody record.
**Pro-se scope:** Prepare & respond only (AI screens and indexes; foundation is laid live by the user).
**Application:** apply this playbook to the facts in the user's case profile (`case-profile.md`).
**Feeds:** Litigation Support (exhibit list), Drafting Counsel, Hearing-Prep Coach, Order Integrity Reviewer.
